  `#`とスペースを開けて見出しテキストを記述する。
  たぶん6段階まで。HTML要素の`h1` - `h6`要素に変換されるから  

  **`h1`は1ページに1つ**というのが通例。
  `h4`, `h5`, `h6`あたりは使う事もないし、使ってるとこも見たことないけど使う事あるのかな？  

  <Blockquote  url="https://developer.mozilla.org/ja/docs/Web/HTML/Reference/Elements/Heading_Elements">
    1つのページに複数の`<h1>`要素を使用することは HTML 標準では認められていますが（入れ子でない限り）、これはよい習慣とはみなされません。
    1 つのページには、ページの内容を説明する1つの`<h1>`要素（文書の`<title>`要素と同様）を置くのが一般的です。  
  </Blockquote>

  markdownlintでは**`h1` -> `h2` -> `h3`**のように順番に使わないと怒られる。
  さらに、見出しの上下1行は空けることもルールとなっている。まあ、理由が無い限りはその方が美しいかもね

## テキストの装飾 (一部GFM)  

  <TabList align="left">
    <Tab tabGroup="decoration" tabName="コード" icon="material-symbols:code" checked>
      ```mdx
      - 斜線

      - 太文字
        - **アスタリスク**
        - __アンダースコア__
      - 斜線・太文字
        - ***アスタリスク***
        - ___アンダースコア___
      - 打ち消し
        - ~~チルダ~~
      ```

    </Tab>
    <Tab tabGroup="decoration" tabName="プレビュー" icon="material-symbols:preview">

        - 斜線・太文字

          - ~~チルダ~~
      </Window>
    </Tab>

  `*`か`_`を使って囲む。一個ずつで囲めば*斜線*、二個ずつで囲めば**太文字**。
  三個ずつで囲むと***斜線かつ太文字***になる。打ち消し線は`~`1個か2個ずつで囲む  

  *斜線*は`<em>`、**太文字**は`<strong>`、~~打ち消し~~は`<del>`に変換される  
  [`~`を使った打ち消しはGFMの仕様](https://github.github.com/gfm/#strikethrough-extension-)

### リンク定義 (Link definitions)  

  ```mdx
  [Too long](https://www.google.com/search?q=markdown+link&rlz=1C1GCEA_enJP1093JP1093&oq=markdown+link&gs_lcrp=EgZjaHJvbWUyBggAEEUYOdIBCTQ4ODVqMGoxNagCArACAQ&sourceid=chrome&ie=UTF-8)
  ```
  URLが長すぎると、本文が大変なことになる  
  なので、`[<link_name>]: <url>`のようにしてリンクを定義しておける。
  表示する文字列とリンク名を`[<text>][<link_name>]`のように並べて使う  

  ```mdx
  [too-long]: https://www.google.com/search?q=markdown+link&rlz=1C1GCEA_enJP1093JP1093&oq=markdown+link&gs_lcrp=EgZjaHJvbWUyBggAEEUYOdIBCTQ4ODVqMGoxNagCArACAQ&sourceid=chrome&ie=UTF-8

  [Too long][too-long]
  ```

  長いことには変わりないが、本文が汚れるのを防ぐことが出来る

## コードブロック  

  <TabList align="left">
    <Tab tabGroup="code" tabName="コード" icon="material-symbols:code" checked>
      ````md {"1":1} {"2":9}
        ```go
        package main

        import "fmt"

        func main() {
          fmt.Println("Hello, world!");
        }
        ```
      ````
    </Tab>
    <Tab tabGroup="code" tabName="プレビュー" icon="material-symbols:preview">
      <Window>
        ```go

        import "fmt"

        }
        ```
      </Window>
    </Tab>
  </TabList>

  最初と最後の行で<code>\`</code>を三つ並べて囲えば、内側の行がコードブロックとなる。
  ~~スペース四行でもできるが、必要ない~~  
  最初の行で言語を指定でき、
  使用できる言語は[github-linguist/linguist - languages.yml](https://github.com/github-linguist/linguist/blob/main/lib/linguist/languages.yml)から確認できる  
  コードスパンは<code>\`</code>一つで囲むだけ  
  コードスパンは`<code>`に変換されるが、コードブロックは一番上で`<pre>`要素に囲まれる  

  `````md
    ````md {"1":1} {"2":9}
      ```go
      package main

      import "fmt"

      func main() {
        fmt.Println("Hello, world!");
      }
      ```
    ````
  `````

  一つ上のコードブロックはこうやって記述している。
  子よりも多い<code>`</code>で囲えば、コードブロック自体を記述出来る  
  コードブロックには更に機能があることが**多いが**、ここでは解説しない

## テーブル (GFM)  

  <TabList align="left">
    <Tab tabGroup="table" tabName="コード" icon="material-symbols:code" checked>
      ```mdx showLineNumbers {"1":1} del={"2":2}
      | column1 | column2 | column3 | column4 |
      |:-------:|:--------|--------:| ------- |
      |  真ん中  |  ひだり  |   みぎ   |   なし   |
      |  真ん中2 |  ひだり2 |   みぎ2  |   なし   |
      ```
    </Tab>
    <Tab tabGroup="table" tabName="プレビュー" icon="material-symbols:preview">
      <Window>
        | column1 | column2 | column3 | column4 |
        |:-------:|:--------|--------:| ------- |
        |  真ん中  |  ひだり  |   みぎ   |   なし   |
        |  真ん中2 |  ひだり2 |   みぎ2  |   なし   |
      </Window>
    </Tab>
  </TabList>

  1行目はヘッダー行  
  2行目では列配置の設定をする。
  `:-:`で真ん中、`:-`で左、`-:`で右、`-`のみで埋めると左揃え（デフォルト）になる。
  `-`の数は1個以上であれば良い  
  3行目からは任意のデータを入力する。列の数は全体で決まり、行は追加した分だけ  

  ヘッダー行では、ヘッダー名はそれぞれ`<th>`要素に変換され、`<tr>`要素で囲われ、更に`<thead>`要素で囲われる  
  列配置の設定の実装はそれぞれ異なるが、align要素かCSSのtext-alignプロパティで制御される  
  データ行（3行目以降）では、各データが`<td>`要素に変換され、`<tr>`要素で囲われ、更に`<tbody>`要素で囲われる  
  そして、`<thead>`要素と`<tbody>`要素は`<table>`要素で囲われる  
  ちなみに、`<th>`要素と`<td>`要素は1行ごとに`<tr>`要素で囲われる  

  GFMの構文で`<tfoot>`を作成するものはない。
  必要ならば、テーブルごとすべてHTMLで記述する必要がある。
  1行目以外のヘッダーの配置なども同様で、Markdown上ではある程度の制限がある

## 脚注  

  ```mdx
  Wikipedia[^wiki]のよくあるあれ[^1]ですよ。

  [^wiki]: Wikipediaだよ
  [^1]: そうそう。あれだわ
  ```

  Wikipedia[^wiki]のよくあるあれ[^1]ですよ。

  [^wiki]: Wikipediaだよ
  [^1]: そうそう。あれだわ

  `[^<name>]`のようにして本文に差し込み、
  別の場所で`[^<name>]:`の後にスペースを空けて脚注の内容を記述する  
  この脚注名自体はMarkdown上の識別子で、本文には上付き文字の1や2など、数字が順番に挿入される  

  挿入される上付き文字の数字は`<sup>`要素に変換される。
  脚注の内容は任意の要素に変換され、本文の最後に配置される。
  `<footnote>`という要素は存在しないので、任意の要素に変換される  

  ちなみに、脚注はMarkdownの仕様でもGFMの仕様でもない。
  `remark-gfm`にはしれっと存在している
